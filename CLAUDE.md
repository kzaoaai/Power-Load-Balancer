# This fork

`kzaoaai/Power-Load-Balancer` is a fork of `chicco-carone/Power-Load-Balancer`.
`AGENTS.md` above is shared with upstream; this file covers only the fork.

## What the fork adds

- Sustained-load shedding on apparent power (VA): it arms at a percentage of
  the budget and sheds after a dwell, on top of upstream's trip recovery
  (`balancing_engine.py`, `power_balancer.py`, settings in `const.py`).
- `water_heater` appliances, shed through their integration's own shed and
  release services where one exists, so a shed is not read as a manual
  change (`appliance_controller.py`).
- A pending-actions sensor (`sensor.py`), notification categories with a
  delivery channel each (`notify_channels.py`, `event_dispatcher.py`).
- Repairs that judge a missing appliance against the entity registry
  (`entity_health.py`).
- Branding in `custom_components/power_load_balancer/brand/`, regenerated by
  `assets/generate_brand.py` (needs `cairosvg`).

## Test and lint

- `./scripts/test` runs the suite (96 tests). It needs `.venv` on Python
  3.12, built from `requirements_test.txt` as `AGENTS.md` describes.
- `uvx ruff@<version pinned in requirements.txt> check .` reports 25

  --check .` is clean.

## Deploy

Production installs the fork through the Home Assistant Marketplace
(Core 2026.11 and later), which tracks GitHub **releases**, not commits on
`main`. A commit without a release never reaches production.

1. Bump `version` in `custom_components/power_load_balancer/manifest.json`.
2. `gh release create vX.Y.Z --target <full sha> --notes-file <file>`
   (`--target` needs the full 40-character sha or a branch name).
3. Install it from the integration's update entity in Home Assistant, then
   restart Home Assistant. The code already loaded keeps running until the
   restart, and the Marketplace raises a repair saying so.

## Conventions

- Upstream comes in by **merge**, never rebase: `main` is public.
  `git fetch upstream && git merge upstream/main`. Upstream releases do
  not appear in Home Assistant any more, so check upstream by hand.
- After a merge, parse-check every config file it touched. `.ruff.toml`
  once merged "cleanly" into two `[lint.per-file-ignores]` tables, which
  is invalid TOML.
- `manifest.json` keeps the fork's identity on merges: its
  `documentation` and `issue_tracker` URLs and its version, with both
  maintainers in `codeowners`.
- Translations: step-level `menu` blocks are dead (Home Assistant reads only
  `menu_options`); the fork's menu labels come from `_build_menu_options()`
  in `config_flow.py`. Flow `error` and `abort` strings belong at section
  level, the only place Home Assistant reads them.
